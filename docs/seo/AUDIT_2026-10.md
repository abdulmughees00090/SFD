## How it was tested
- 47 pages re-scanned: 0 broken links, 0 duplicate titles/descriptions/H1, 0 JSON-LD errors, 0 mixed content.
- 66 behavioural tests on both API routes and the service worker, all pass.
- Before/after proof: crash on empty body, formula stored verbatim, bad email accepted, 2 MB message stored, `URIError` on `%`, HTML injected via toast: all reproduced on the old code and gone on the new.
- Headless Chromium, 1440px and 375px, original vs fixed: careers, contact, products and an article are pixel-identical; no JS errors. Homepage differs only inside an animated hero region that also differs between two runs of the original.

## Needs the owner's decision (not changed)
1. **Public demo credentials** (`admin123`) on `/products/`, kept per Q4. Anyone can sign in; make sure the demo tenant holds no real data and cannot send email/SMS.
2. **Unverifiable claims**: the `/about/` case study ("12-location chain, costs cut 25%") and "50,000+ downloads" (AnyDown). Search engines and AI systems quote these. Keep only if you can substantiate them; otherwise reword.
3. **`@silverfoxdyn` Twitter/X handle** appears in 36 pages' meta tags, but no X profile is linked anywhere. SEO_RULES forbids unverified social accounts. Confirm it exists or remove it.
4. **Nora Eve** is a café plus bridal boutique, and now redirects to `noraeve.co.uk`. "E-commerce bridal store" is partly inaccurate; update the URL and wording.
5. **Careers**: pages still carry the old `keywords` meta and `Islamabad` geo tags; harmless, ignored by Google and Bing.
6. **Images**: hero PNGs are 85–133 KB. Optimised WebP versions already sit in `unused-images/`. Switching 47 pages to `<picture>` touches markup everywhere, so I left it for a separate change.
